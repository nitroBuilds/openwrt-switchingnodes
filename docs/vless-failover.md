# Автопереключение VLESS между подписками

В основных настройках под выбором ноды включите чекбокс
**Автоматический выбор VLESS-ноды** (**Automatic VLESS node selection**) и нажмите
**Save & Apply**. Основной нодой должна быть VLESS-нода из подписки.
Механизм по умолчанию выключен; shunt, ACL и отдельные SOCKS-секции он не меняет.
Чтобы отключить автоматический выбор, снимите чекбокс и снова нажмите
**Save & Apply**. Состояние сохраняется в `passwall2.@global[0].vless_failover`
как `1` (включено) или `0` (выключено).

Параметры по умолчанию:

- URL: `https://www.youtube.com/`.
- Пауза между проверками: 300 секунд, в том числе после запуска/переключения.
- Таймаут полного GET-запроса: 10 секунд.
- Переключение после одной неудачной проверки; порог можно увеличить в UI.

Запрос идёт через SOCKS-вход глобального прокси, включая разрешение имени сайта.
Успех — завершённый GET с конечным статусом 2xx и непустым телом. Тело не
сохраняется на диск. Пустой ответ 204, ошибка TLS, HTTP-ошибка, оборванная загрузка
и таймаут считаются отказом. TLS-сертификат проверяется.

При отказе выбирается следующая подписка в порядке UCI-секций `subscribe_list`,
а в ней — следующая VLESS-нода в порядке UCI-секций `nodes`. Например:
`A1 → B1 → C1 → A2 → B2 → C2 → A1`. Подписки без подходящих нод пропускаются.
При отсутствии другой подходящей подписки текущая нода остаётся выбранной.

Принадлежность определяется так же, как при обновлении подписок:
`node.add_mode = 2`, `node.group` соответствует `subscribe_list.remark`
без учёта регистра. Используйте разные названия подписок. Ручные ноды и
другие протоколы не участвуют. Сохранённые позиции автоматически обходят
удалённые ноды после обновления подписки.

При переключении новый ID сохраняется в `passwall2.@global[0].node`, затем
PassWall2 полностью перезапускается. Соединения могут прерваться. Позиции очереди
хранятся в `/tmp/etc/passwall2_tmp/vless_failover.json`: переживают перезапуск
сервиса, но сбрасываются при перезагрузке роутера. Автовозврата к первоначальной
ноде нет: рабочая нода используется до очередной неудачной проверки.

События записываются в обычный журнал PassWall2 с префиксом `VLESS failover`.
Отказ YouTube или всего интернет-соединения также вызовет перебор: HTTP-проверка
определяет доступность сайта через ноду, а не причину отказа. Если все ноды
недоступны, очередь продолжается с указанной паузой.

## Проверки

Из корня репозитория: `python3 -m unittest discover -s tests -v`.
Для Lua-тестов нужен `lua`, `luajit` или Python-пакет `lupa`.
Тесты используют подставные ответы HTTP и операции сервиса. Проверка на OpenWrt
должна дополнительно подтвердить получение тела YouTube, перезапуск процессов
и смену ноды при недоступном сервере.
